# Tamayura バーチャル試着サイト 設計メモ（STEP 1〜2）

## 1. 技術構成

| 項目 | 採用 | 理由 |
|---|---|---|
| 作り | HTML / CSS / JavaScript のみ | ファイルを置くだけで動く。サーバー側のプログラム不要 |
| 画像処理 | Canvas API（ブラウザ標準） | 重ね合わせ・乗算・回転・保存まで標準機能で足りる |
| ライブラリ | **使わない** | Fabric.js / Konva.js は多機能だが、今回必要なのは「1枚の画像を動かす」だけ。自前の約700行で済み、読み込みも軽く、将来の独自表現（ジャグア風の描画）も自由に書ける |
| 公開先（おすすめ） | GitHub Pages（無料） | このリポジトリをそのまま公開できる。https になるのでスマホの「保存」「シェア」が動く |
| 外部サービス・有料API | なし | 写真を外に出さないため |

外部に通信するのは Google Fonts（文字の形のデータ）だけで、写真は一切送信しません。

### ファイル構成

```
index.html        … 試着ページ本体
css/style.css     … 見た目（色は先頭の :root で一括変更）
js/config.js      … 設定（予約URL・料金・サイズ・透かし文字など）★運用で触るのはここ
js/designs.js     … デザイン一覧 ★デザイン追加はここ
js/app.js         … 動き（通常は触らない）
designs/          … デザイン画像（透過PNG / SVG）
```

## 3. 初期版では実装しない方がよい機能（理由）

| 機能 | 理由 |
|---|---|
| AIの部位認識・曲面変形 | 重い AI モデルの読み込みが必要で、スマホで遅くなる。精度調整にも時間がかかる。まず「試せること」を優先 |
| 実寸の正確な測定 | 写真の距離・角度が人それぞれで、正確な cm は出せない。今は「部位ごとの想定」で目安表示 |
| 予約システム連携・画像の自動送付 | 画像をサーバーに送る仕組みが必要になり、「サーバーに保存しない」方針と両立させる設計が要る |
| お気に入り・アカウント | ログイン・データ保存が必要になる |
| 複数デザイン同時配置 | 仕組みは用意済み（config.js の MAX_LAYERS）。操作が複雑になるため初期版は1つ |

```

├────────────────────┤
│ [Before|After]      ⟲  🗑 │
│                            │
```

PC（横幅900px以上）では、左に写真・右に操作パネルの2列になります。

## 5. バーチャル試着の仕組み

1. 選んだ写真を、ブラウザの中で最大2000pxに縮小して保持（サーバーへは送らない）
2. デザイン画像を「形はそのまま・色だけジャグア色（ブルーブラック）」に塗り替える
3. **乗算（multiply）** で写真に重ねる → 肌の陰影・きめが透けて、上に貼ったのではなく「肌に描いた」ように見える
4. ほんの少しの「にじみ」を足して、線の硬さをやわらげる（操作中は軽くするため省略）
5. 保存時は、画面と同じ処理で元写真サイズの画像を作り、右下に「Virtual Try-on by Tamayura」を入れる

### サイズの考え方（Tamayura のサイズチャートに合わせています）

- デザインの「短い辺 × 長い辺」が、サイズチャートの型（正円 / 楕円 / 長い円）のどれかに収まる、いちばん小さい区分をそのデザインのサイズとする
  - 例：8cm区分 ＝ 80×80mm / 60×110mm / 45×130mm のどれかに収まる
  - サイズボタンを押すと、デザインの縦横比に合わせて、その区分の型に収まる最大の大きさになる
- 写真から実寸は分からないため、「撮った部位」ごとに **写真の短い辺 ≒ ◯cm** と想定して換算（config.js の BODY_PARTS）
- 表示は「約6×11cm」「8cm区分 ¥4,950」「≒ 1000円札の半分くらい」など、あくまで目安
- 料金は通常料金（デザインから選ぶ場合）を表示。オーダー料金も config.js に登録済み（オリジナルデザイン機能を作るときに使用）

将来の精度アップ案：写真に 500円玉（直径2.65cm）や名刺を一緒に写してもらい、その大きさを基準に換算する「基準合わせ」機能（AI不要・無料で実装可能）。
